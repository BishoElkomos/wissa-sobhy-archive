# SEO Strategy

## Principles

Search visibility must follow useful, authoritative archival content. Do not create thin pages merely to capture keywords.

## URL model

Use stable, descriptive slugs:

- `/ar/wissa-sobhy`
- `/ar/timeline`
- `/ar/people/[slug]`
- `/ar/events/[slug]`
- `/ar/places/[slug]`
- `/ar/sources/[slug]`
- `/ar/archive/photos/[slug]`

English can use `/en/...` with independent metadata and canonical/hreflang handling.

## Structured data

Use JSON-LD where appropriate for Person, Article, Event, ImageObject, BreadcrumbList, and WebSite/SearchAction. Never use structured data to claim facts not supported by the visible page and sources.

## Indexation

- XML sitemap for public canonical records
- robots.txt
- canonical URLs
- hreflang for translated equivalents
- noindex for drafts, private records, search-result permutations, and internal/admin views

## On-page requirements

Each public record should have one clear H1, useful introductory text, descriptive title/meta description, contextual internal links, accessible image alt text, and a visible source/provenance section when applicable.

## Performance

Prefer optimized responsive images, minimal client JavaScript, static rendering where possible, lazy loading below the fold, and measured Core Web Vitals.

## Editorial SEO rule

The archive should earn search visibility through original organization, provenance, contextual linking, and genuinely useful historical records—not keyword stuffing or duplicate copies of third-party articles.

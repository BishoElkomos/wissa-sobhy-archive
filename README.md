# 📚 أرشيف القمص ويصا صبحي تادرس

**مشروع أرشيفي رقمي تاريخي** يوثق سيرة وخدمة القمص ويصا صبحي تادرس، مع حفظ المصادر والأخبار والصور والوسائط والسياق الكنسي بطريقة قابلة للتتبع.

## 🎯 أهداف المشروع

- توثيق السيرة والخدمة بمصادر محددة.
- حفظ الذاكرة الكنسية للأجيال القادمة.
- توفير مادة منظمة للباحثين والدارسين.
- حفظ تاريخ التعديلات والمصادر عبر GitHub.
- إتاحة أرشيف قابل للبحث ومتعدد اللغات.

## 📁 البنية الحالية

الموقع العام يعتمد على بنية موحدة:

**الرئيسية → القمص ويصا صبحي → الأنبا أغابيوس → الأنبا بقطر → تاريخ الإيبارشية → المصادر والأخبار والوسائط → البحث**

### الصفحات الأساسية

- `website/wissa.html` — السيرة + الخط الزمني + الأحداث في صفحة موحدة.
- `website/agabius.html` — السجل التاريخي للأنبا أغابيوس.
- `website/boktor.html` — السجل الحالي للأنبا بقطر.
- `website/diocese.html` — تاريخ إيبارشية ديرمواس ودلجا.
- `website/sources-media.html` — مركز المصادر والأخبار والوسائط.
- `website/search.html` — البحث.

الصفحات القديمة للسيرة والخط الزمني والأحداث والمصادر والوسائط محفوظة عند الحاجة كمسارات توافقية، ولا تُعاد إلى التنقل الرئيسي.

> `evidence.html` متقاعد من الواجهة العامة. خريطة الادعاء ← المصدر موجودة داخليًا في `data/evidence-matrix.json`.

## 🧾 نظام التوثيق

المشروع يميز بين حالات الأدلة بدل استخدام كلمة «موثق» بشكل مطلق:

- `primary_source` — مصدر أولي رسمي.
- `cross_supported` — أكثر من مصدر مستقل أو متوافق.
- `secondary_published` — مصدر منشور ثانوي.
- `source_recorded` — المصدر مسجل لكن لا يعني تصديق كل تفصيل.
- `indexed_not_fully_retrieved` — المصدر معروف ولم تُسترجع مادته كاملة.
- `needs_verification` — يحتاج تحققًا.
- `metadata_only` — بيانات وصفية فقط.
- `link_only` — الرابط موجود دون فحص المحتوى.

القاعدة الأساسية: **المصدر يجب أن يدعم الادعاء المحدد، وليس مجرد الموضوع العام.**

## 🗂️ ملفات المنهج والأدلة

- `data/source-registry.json` — السجل الأساسي للمصادر.
- `data/source-additions-2026-09.json` — إضافات المصادر الحديثة.
- `data/source-corrections-2026-09.json` — تصحيحات وتقوية السجل.
- `data/evidence-matrix.json` — خريطة الادعاءات ومصادرها.
- `data/archive-methodology.json` — منهج الأرشفة الدائم.
- `data/media-registry.json` — سجل التسجيلات والفيديوهات.
- `data/photo-registry.json` — سجل الصور.
- `PROJECT-HANDOFF.md` — نقطة الاستئناف الرسمية عند الانتقال إلى محادثة جديدة.
- `ARCHIVE-DECISIONS.md` — القرارات الأرشيفية الدائمة.

## 🔐 مبادئ مهمة

- لا تُستخدم الصفة التاريخية «وكيل الإيبارشية» كصفة حالية.
- لا يُرفع محتوى اجتماعي أو صورة غير مفحوصة إلى دليل مستقل تلقائيًا.
- لا تُحسب النسخ المنقولة كمصادر مستقلة دون إثبات استقلالها.
- لا تُنسب أدوار شخصية في الأحداث الحساسة إلا بما يثبته المصدر.
- الصور الأرشيفية لا تُعدل ملامح الأشخاص بالذكاء الاصطناعي.
- كل تغيير جوهري يجب أن يكون قابلًا للتتبع في Git.

## 🚀 النشر

المشروع يستخدم GitHub Actions للتحقق والبناء، وVercel كبيئة الإنتاج الكانونية للموقع. نجاح CI لا يعني تلقائيًا أن deployment معين هو النسخة الحية؛ يجب التحقق من deployment نفسه عند الحاجة.

## 🔎 العمل المفتوح

المسار الحالي هو **Archive Integrity Phase**، ويشمل:

1. claim-level provenance.
2. مراجعة السجلات القديمة والروابط العامة غير المحددة.
3. تحسين provenance للصور والوسائط.
4. حفظ نسخ المصادر المهمة عندما يكون ذلك متاحًا ومشروعًا.
5. استكمال البحث في المصادر 2007–2015 والمصادر الدولية واللغات الأجنبية.
6. التحقق النهائي من CI وproduction بعد كل تغيير جوهري.

Issue #4 مخصص لاسترداد المصادر الأولية والدولية للفترة 2007–2015.
